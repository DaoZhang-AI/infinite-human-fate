# 写卡资料接口 v1

用户在人物详情选择事件、处理 User 关系，并核对最终预览后，可以下载 JSON，或主动传送给已安装的写卡插件。模拟人生不会自动广播整场聊天、文件名、连接配置或凭证。

```json
{
  "format": "ihf-card-material",
  "version": 1,
  "character": { "name": "NPC", "role": "char", "origin": "谨慎", "personality": "更愿意信任别人" },
  "events": [{ "id": "source-fingerprint", "text": "NPC曾与{{user}}共同修复旧物。", "mode": "placeholder" }]
}
```

接收插件在同一个酒馆页面监听 `document` 上的 `ihf:card-material` 事件。`event.detail.payload` 是上述结构的独立副本。接收方校验 `format` 和 `version`，保存到自己的待编辑资料区后，同步调用 `event.detail.accept()`。没有接收方确认时，界面会提示资料尚未送达，可改为下载导入。此接口尚未与未来的写卡插件联调。

处理方式：

- `placeholder`：保留关系，实际用户名替换成 `{{user}}`，已有占位符保持不变。
- `omit`：去掉包含用户称呼或身份标记的整句，可能损失该句中的其他信息，预览时可再调整。
- `abstract`：使用用户填写或现有模型生成的独立经历总结，不自动把换名字称为抽象化；必须先有总结才能导出。生成内容仍需核对。

资料只携带所选事件与当前性格，不携带所有行动历史，避免未选事件沿性格日志再次泄露。姓名、性格和事件文本均可在最终预览修改。公开分享前仍应检查实际人物称呼与情节。

记录编辑保存在本局记忆文件的 `dossiers`、`personBlocks`、`recordEdits` 中。删除记录会保留同步用的删除标记；原聊天正文不被修改。人物黑名单保留原人物资料供恢复，不做无依据姓名合并。念头的手工修改按真实正文前缀参与回放，重抽回原前缀时仍保留原有撤销规则。
